How the pieces connect

Preparation happens once. GitHub Pages publishes the app and saved data; the visitor's browser performs the display and analysis. No sports-site fetch is needed during playback.

Walk through the planned data flow

Open → load and check

The loader reads the saved JSON file and checks its required facts. The matchup stays visible. When data is ready, Play is available. The browser holds viewing progress in memory; refreshing returns to the beginning.

Files: app.js → model.js → bills-chiefs.json

Play → one logical clock

The playback controller reveals the axes, then advances events over about seven minutes at 1x. The chart, scrolling ticker and bubbles all read that same position. Pause and speed changes preserve progress.

Proposed initial speed choices: 0.5x, 1x, 2x, 4x, 8x. These and bubble timing can be tuned after trying the real replay.

Files: playback.js → replay-chart.js + events.js

Hover a yellow dot → hold and read

Inspection adds a separate pause reason. Leaving the marker removes that reason without cancelling a deliberate manual pause. Focus/tap provide equivalents when hover is unavailable.

Files: events.js ↔ playback.js

Finish → explore the same facts

The box score and analysis views use the shared model. Chiefs appear first; Bills and Compare both remain available. Changing the lower chart's selection restarts only that analysis.

Fourth-down bars come from actual completed fourth-down decisions. Penalty-nullified plays and kicks taken on earlier downs are excluded from that count.

Files: model.js → analysis.js + fourth-downs.js

Unavailable data → message and Retry

Keep the matchup visible and explain that the game cannot be displayed. Retry reads and checks the same file again. A continued failure stays explicit; the app does not invent plays or substitute a misleading partial replay.

Files: app.js + model.js

Checks still needed in the build

These source checks establish feasibility. The app's prepared data and charts do not exist yet.

  • Reconcile every scoring transition and quarter total.
  • Keep returns credited to the right team.
  • Handle sacks and self-recovered fumbles without counting movement twice.
  • Check all 13 fourth-down decisions and exclude nullified plays.
  • Verify hover/manual pause, timing and speed changes.

A revealing edge case: the Chiefs' missed field goal was on third down; the late tying field goal was on first down. Both belong in the replay, neither belongs in fourth-down decision bars.

Why “passing yards” needs care

The main vertical total uses net offense + returns, so sack losses reduce it. The box score and passing-over-time chart use gross passing yards, matching the quarterback's passing line. The legend explains the difference. The same data model computes both explicitly.

Mirrored horizontal scores show actual points on each side; the distance between paths is not the lead.

How we’ll try and share it

Local preview after building: node tools/serve.mjs, then open http://127.0.0.1:4173/. Node is already available here.

Tests: node --test. Publishing preparation: node tools/publish.mjs. GitHub Pages will publish main /docs; the actual URL comes from GitHub once the repository is set up.

Visitors only need a browser. The short demo video and public repository remain submission requirements.

Build order
  1. Prepare the real game and verify its facts.
  2. Build the page, loader/error flow and main chart.
  3. Connect playback, ticker and event inspection.
  4. Add box score and yards-over-time exploration.
  5. Add fourth-down analysis, hands-on review, and final checks.

Additional games and live importing remain later work. Synthetic tests for missing event categories stay separate from the real replay.

Teaching takeaway

One source of calculations keeps related views consistent. An agent should be able to trace a displayed number back to the same checked events, rather than computing it differently in every chart.
