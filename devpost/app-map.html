Game in motion
How the app fits together

One saved Bills–Chiefs game becomes a visual replay, a yardage comparison, and a view of fourth-down decisions.

January 23, 2022 · final score Bills 36, Chiefs 42 · source snapshot 04e7d78 · October 5, 2026

The main pieces

  • Checked game data: site/data/bills-chiefs.json contains 189 events in source order. The app reads this saved file; watching needs no live sports service.
  • Numbers: site/js/model.js calculates cumulative yards, scores, quarter totals and fourth-down summaries.
  • Playback and views: app.js coordinates the main clock; replay-chart.js draws the main D3 chart; events.js handles key moments. analysis.js and fourth-downs.js provide the final analysis views. These files are in site/js/.
  • Sharing: tools/publish.mjs prepares an explicit set of public files in docs/. Uploading and enabling a public link are separate shipping steps.

  1. Open site/js/model.js and search fourthDownSummary. Go-for-it rate divides attempts by all valid decisions. Success rate divides conversions by attempts. No attempts produces null, displayed as N/A.
  2. Open site/js/fourth-downs.js and search function refresh(). It uses that summary to create each team's count button; the click listener opens the bars for the selected teams.
  3. In the same file, search function draw(teams). It draws a bar per valid decision. Height means yards needed; color means outcome. details(event) supplies clock, player description and score before/after on hover, focus or click.

A practice to reuse

Make a request observable, verify it, try it, then save it. During this build, the requested clearer axes became exact bold score badges with brief yellow scoring highlights and a prominent “Cumulative yards gained” heading. Browser review checked readability; learner feedback approved the result.

The score behavior is also checked in tests/model.test.mjs, under exact score labels and scoreboard switch together, briefly highlight, and reset. It checks the score before and at a scoring transition, the highlight settling, and Replay resetting. A test establishes the numerical behavior; trying the browser establishes whether the presentation communicates it.

Another concrete requirement appears in devpost/prd.md: 3 successful attempts out of 4 means 75%. tests/fourth-downs.test.mjs checks the denominator separately from the go-for-it rate. Clear examples help an agent build the intended behavior and help a reviewer detect mistakes.

Optional small practice for later

Ask the agent to change only the yardage heading in replay-chart.js, agree on the wording, refresh the preview and check readability. If you keep the change, save a checkpoint and regenerate docs/. This optional edit has not been performed as part of the wrap-up.

Run and reopen

Open the project folder in Codex and ask “Start the football app preview.” Or run node tools/serve.mjs from the project folder, then open the local app. After turning off the PC, start the preview again.

For checks: node --test and node tools/verify-game.mjs. After a kept app change: node tools/publish.mjs refreshes the prepared public copy without uploading it.

Reopen this guide by opening devpost/app-map.html. It works offline with scripts disabled. The app itself needs its local preview server. See README.md for startup and data attribution.
